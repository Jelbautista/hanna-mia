# ADR-002 — Sincronización por bitácora de operaciones de dominio idempotentes

- **Estado**: Propuesta · **Fecha**: 2026-11-19 · Detalle: [SYNC_STRATEGY](../architecture/SYNC_STRATEGY.md)

## Contexto

Los comercios trabajan con conectividad intermitente y, a veces, con varios celulares a la vez. Una
venta perdida o duplicada destruye la confianza. El prompt prohíbe "última escritura gana" para
ventas, pagos, inventario y comprobantes.

## Decisión

- El dispositivo escribe localmente y, **en la misma transacción**, encola una **operación de
  dominio** (`sale.complete`, `inventory.adjust`, …) con `op_id` (uuid7) y `device_seq`.
- El servidor aplica cada operación en una transacción, con idempotencia por `op_id` (resultado
  guardado en `sync_events`), validación completa y despacho al módulo dueño.
- El pull es incremental por cursor (`sync_changes.seq`).
- Los conflictos se resuelven **por dominio**: hechos append-only para dinero; deltas conmutativos
  para inventario; conteos convertidos en delta con revisión; combinación por campo con prioridad de
  rol para catálogo; última escritura gana solo para preferencias; comprobantes con autoridad
  exclusiva del servidor.

## Alternativas consideradas

| Alternativa | Por qué no |
|---|---|
| Replicación de filas (CouchDB/PouchDB, PowerSync, ElectricSQL) | Sincroniza estado, no intención: se pierde el "por qué" del cambio; las reglas de dominio (anulación, conteo) quedan fuera; fuerte dependencia de la herramienta |
| CRDT genéricos | Excelentes para texto o colecciones, pero las reglas financieras no son conmutativas en general (anulaciones, saldos, correlativos) |
| Online-only con caché | Incumple el requisito offline-first |
| Última escritura gana | Prohibido para dominios financieros; pierde datos de forma silenciosa |

## Consecuencias

- ✅ Idempotencia y auditoría naturales (cada cambio tiene `op_id`).
- ✅ Las mismas reglas valen en línea y sin conexión (un solo servicio de dominio).
- ⚠ Hay que mantener el catálogo de `op_type` versionado (N y N−1).
- ⚠ Lógica duplicada mínima en el dispositivo (reglas puras en Dart) para el efecto local inmediato; el servidor es la autoridad.
